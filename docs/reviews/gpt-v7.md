## Review

The v2–v6 fixes are present, but v7 is still a **FAIL** for tomorrow morning. The principal blocker is that audio unlocking and retry playback happen in React effects, outside the child’s tap—exactly where mobile browsers can reject playback.

1. **[P1] Start and retry do not execute audio inside the user gesture.** [Story.tsx:144](/Users/rish_ai/StoryTime/src/screens/Story.tsx:144) calls `unlock()` from `useEffect`; retry at [Story.tsx:162](/Users/rish_ai/StoryTime/src/screens/Story.tsx:162) merely changes state and again starts playback later in an effect. On iOS Safari and stricter Android configurations, both can reject with `NotAllowedError`, so even “Try again” may loop forever. `unlock()` also awaits the first element before touching the clip and speech engines at [player.ts:30](/Users/rish_ai/StoryTime/src/lib/audio/player.ts:30), losing transient user activation. **Change:** make Start/Retry handlers synchronously invoke `unlock()` and the first `play()`; initiate narration, clip, and speech unlocks before awaiting anything. Keep an explicit tap-to-start overlay if navigation prevents this.

2. **[P1] The installed GitHub Pages PWA has an out-of-scope start URL.** Deployment builds under `/StoryTime/`, but [vite.config.ts:19](/Users/rish_ai/StoryTime/vite.config.ts:19) hard-codes `start_url: "/"`. The installed icon can open `github.io/` instead of the app, or make the manifest ineligible because the start URL is outside its default scope. **Change:** use `start_url: "."` and `scope: "./"`, or derive both from `BASE_PATH`; verify the generated manifest at `/StoryTime/manifest.webmanifest`.

3. **[P1] A clean deployment can ship every story with missing narration.** Generated library audio is gitignored, while [deploy-pages.sh:5](/Users/rish_ai/StoryTime/scripts/deploy-pages.sh:5) only runs `npm run build`; [package.json:8](/Users/rish_ai/StoryTime/package.json:8) runs neither audio generation nor library validation. This checkout happens to contain ignored audio, but a fresh machine or CI deploy will not. Every built-in story then reaches the retry screen. **Change:** make deployment run validation and require a complete audio artifact supplied by CI or a versioned release bundle. Fail before publishing when any referenced file is absent.

4. **[P1] The “contract test” does not enforce the claimed content/audio contract.** [validate-library.test.ts:45](/Users/rish_ai/StoryTime/scripts/validate-library.test.ts:45) checks only monotonic timestamps; it never confirms audio files exist, media duration matches `audioMs`, or tokens still correspond to the TTS boundaries produced by [gen-audio.py:52](/Users/rish_ai/StoryTime/scripts/gen-audio.py:52). Editing narration text or tokens after generation can therefore produce plausible-looking, wrong karaoke. It also does not require a non-empty title/pages or validate unique slugs; an empty `pages` array strands the machine in `narrating`. **Change:** add schema validation, asset existence/duration checks, and persist a normalized transcript or content hash from generation for independent verification.

5. **[P1] The learner model still treats spelling as pronunciation.** [validator.ts:24](/Users/rish_ai/StoryTime/src/lib/phonics/validator.ts:24) deletes apostrophes, so `"can't"` becomes `cant` and may pass as four taught letters. The substring blacklist at [validator.ts:34](/Users/rish_ai/StoryTime/src/lib/phonics/validator.ts:34) catches selected digraphs but not silent letters, alternate pronunciations, schwa, or graphemes split across morphemes. This can both teach a false decoding and reject a valid one. **Change:** select magic/read-back words from a curated pronunciation-backed decodable lexicon keyed by taught GPCs; preserve apostrophes and fail closed on words absent from that lexicon.

6. **[P1] Parent recordings can speak the magic word before the child’s turn.** Untimed recordings are divided evenly by token count at [Story.tsx:81](/Users/rish_ai/StoryTime/src/screens/Story.tsx:81). Human speech is not evenly paced, so stopping at the estimated magic-token boundary can happen after the parent has already said it. Recording length is also measured in the asynchronous `FileReader.onload` at [record.ts:23](/Users/rish_ai/StoryTime/src/lib/audio/record.ts:23), adding encoding time to the estimate. **Change:** record narrator-prefix and reread audio separately, excluding the magic word from the prefix, or run real forced alignment. Capture duration at stop time or from decoded media metadata.

7. **[P1] Any IndexedDB initialization error leaves the app permanently unready.** The startup async function at [family.tsx:49](/Users/rish_ai/StoryTime/src/lib/family.tsx:49) has no catch or `finally`; a rejected read/write means `setReady(true)` is never reached. The family sees a permanent loading state with no recovery path. **Change:** load under `try/catch/finally`, show a grown-up recovery screen, and allow retry, storage reset, or a clearly labelled temporary session.

8. **[P2] “Home” does not cancel multi-step audio workflows.** The modelling handler at [Story.tsx:174](/Users/rish_ai/StoryTime/src/screens/Story.tsx:174) continues through several awaited prompts and clips. If Home is tapped, the current clip stops, but the continuation can start the next clip on the Home screen and later send `MODEL_DONE` to the abandoned actor. **Change:** introduce a session-scoped abort/generation token, invalidate it in `home` and unmount cleanup, and check it after every await before playing or sending.

9. **[P2] Resume/result identity is the word, not the reading occurrence.** Sessions store only `page` and word results at [store.ts:32](/Users/rish_ai/StoryTime/src/lib/store.ts:32); pending detection at [Story.tsx:68](/Users/rish_ai/StoryTime/src/screens/Story.tsx:68) suppresses any later occurrence of the same magic word. The contract allows the same word on multiple pages, so intentional repetition will silently lose a child turn. **Change:** give each magic occurrence a stable ID such as `page:token`, store that ID in results/session state, and persist the actual machine phase.

10. **[P2] The cache cannot guarantee IndexedDB safety, and audio object URLs leak.** Workbox limits entries, not bytes, at [vite.config.ts:27](/Users/rish_ai/StoryTime/vite.config.ts:27); forty audio responses can still compete with family photos/recordings for the origin quota. Separately, [player.ts:45](/Users/rish_ai/StoryTime/src/lib/audio/player.ts:45) retains every full data-URL string and object URL forever, including obsolete re-recordings. **Change:** revoke object URLs when superseded, remove the unbounded map, store media as `Blob`s rather than base64 JSON, monitor `navigator.storage.estimate()`, and provide visible storage/export/delete controls.

11. **[P2] Recorder failures can leave the builder stuck.** [record.ts:14](/Users/rish_ai/StoryTime/src/lib/audio/record.ts:14) handles only successful data and stop events: there is no `MediaRecorder.onerror`, `FileReader.onerror`, inactive-state guard, or cancellation API. A failed read can leave `toggleRec()` awaiting forever; a cleanup/button stop race can reject without restoring UI state. **Change:** make stopping idempotent, settle exactly once on every recorder/reader outcome, expose `cancel()`, and clear `recording` in `finally`.

12. **[P2] Duplicate page text aliases photos, narration, and magic choices.** All media is keyed by the sentence string at [AddStory.tsx:38](/Users/rish_ai/StoryTime/src/screens/AddStory.tsx:38). Repeated pages such as “Run!” share one key, so recording or changing one silently changes both. The builder also self-certifies every retelling criterion as true at [AddStory.tsx:66](/Users/rish_ai/StoryTime/src/screens/AddStory.tsx:66), making that part of the content contract meaningless. **Change:** maintain pages as `{id, text}` objects with stable IDs, and either collect the checklist from the parent or mark family stories as parent-authored with a distinct validated contract.

**Tomorrow-morning verdict: FAIL.** A built-in story may work after browser-specific autoplay luck or prior media permission, but the normal installed-PWA path is not dependable enough for the family.

**Single riskiest assumption:** that a React `useEffect` triggered after the Start/Retry tap still possesses mobile browser user activation for audio playback.
